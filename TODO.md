[ ] **Rich workflow model + visual editor (Plan 45 candidate):** Our current workflow model inverts the Wiz/n8n/Temporal workflow concept — every `WorkflowStepSchema` entry runs an agent (via `handle_mission(step.brief)` → Planning Agent → TaskPlan → dispatch → agents), so each step is a coarse "run this capability" rather than a precise "call this tool / branch on this condition / ask this human". A workflow should be **deterministic orchestration where LLMs are nodes, not orchestrators** — the graph decides what runs next, and AI calls are scoped functions within it. This inverts cleanly with agents: agents are for open-ended exploration (LLM reasons, picks tools), workflows are for known processes (graph runs, LLMs are function calls). Mission Control needs both. Scope breaks into three layers: **Layer 1 — Node model (backend schema).** Replace `WorkflowStepSchema` with a discriminated union of typed nodes: `AgentStepNode` (existing — runs an agent via handle_mission, backwards-compatible), `ToolCallNode` (direct tool invocation with typed input/output, e.g. `update_threat_severity(id, severity)`), `LlmCallNode` (constrained one-shot LLM call with fixed prompt template + structured output schema, not a full agent), `ConditionNode` (boolean expression over variables, emits true/false branches), `HumanInputNode` (sends a message via a channel adapter and blocks the run waiting for reply on the same channel), `NotificationNode` (fire-and-forget via channel adapter), `BranchNode`/`MergeNode` (explicit DAG structure for branching/joining), `SubWorkflowNode` (invoke another workflow inline with depth limit — this is the composition primitive for Plan 44). Plus a variable binding language: `{{trigger.field}}`, `{{steps.nodeId.output.field}}`, expression evaluation for conditions. **Layer 2 — Executor (backend runtime).** Rewrite `WorkflowRunService` as a node-type dispatcher walking the DAG topologically. Each node type gets a small async executor function. Variable substitution layer evaluates `{{...}}` refs against accumulated run state. Human nodes park the run in `waiting_on_human` state in Redis until a matching reply arrives (reuse existing channel gateway for inbound handling). Condition nodes branch the walk. Sub-workflow nodes recurse with depth limit. Cost + duration tracking per-node + per-run. Temporal migration (Plan 16) is the obvious production path once this lands — the dispatcher shape maps 1:1 to Temporal activities. **Layer 3 — Visual editor (frontend).** React Flow-based graph editor — `@xyflow/react` is already in `package.json` from the old workflows page and `WorkflowsPage` has a DAG viz component we can build on. Features: drag-drop node palette keyed by node type, inline editing of node config (prompt templates, tool args, condition expressions), variable picker autocompleting `{{steps.xxx.yyy}}` from upstream node outputs, run history panel on the right showing past executions with success/failure markers (like the Wiz "Run History" drawer), test run with sample input, version control (each save bumps `version`, `locked_at` field already exists), save + publish flow. **Phasing (5 phases, ~3-4 focused weeks):** Phase 1 — new node schema + executor, keep `AgentStepNode` backwards-compatible so existing workflows still run. Phase 2 — variable binding language + expression evaluator. Phase 3 — `HumanInputNode` with channel gateway integration (depends on the channel gateway being solid — telegram already works, needs testing with real human pauses). Phase 4 — React Flow visual editor replacing the current read-only WorkflowsPage. Phase 5 — `SubWorkflowNode` + Plan 44 integration (plan task as workflow invocation). **Downstream unlock:** once this lands, Plan 42 autonomous mode becomes much more powerful — a mission plan can have tasks like "run the nightly-ci workflow", and those workflows can contain human approval steps that actually pause the run, tool calls that don't require agent reasoning, and scoped LLM calls for narrow decisions. The Wiz threat-response example is the template: Trigger → AI summarize → Confidence check → branch → tool updates + human asks + notifications. Rough total scope: 3-4 weeks of focused work, should be its own formal plan doc when ready to tackle.
